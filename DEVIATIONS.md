# Deviations

Where this project diverges from the jig standard (vendored at `docs/STANDARDS.md`). Every entry
has a justification and, where the divergence should eventually close, a trigger. Deviations are
documented, never silent — an empty file means full compliance.

| Deviation                                                                   | Why                                                                                                                                                                                                                                                                                                                                                      | Reconverge when                                                                           |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Bun repo: Bun for install, workspaces, runtime, test and compile (not pnpm) | The deliverable is a compiled single-file binary (`bun build --compile`), and the PRD mandates Bun + OpenTUI (native Zig core built for the Bun runtime). The standard's scoped exception; one toolchain for `apps/cli` and `apps/www`.                                                                                                                  | The binary stops being a deliverable.                                                     |
| `docs/PRD.md` outranks `AGENTS.md` on product scope and technical direction | The PRD is the product's source of truth; agent rules are operating procedure. Conflicts are followed PRD-first and flagged.                                                                                                                                                                                                                             | Never — standing project rule (see `AGENTS.md`).                                          |
| No Infisical: no env values                                                 | Nothing in development, CI or deploy needs an env value. The CLI's env overrides (`BEEPTUI_ENDPOINT`, `BEEPER_ACCESS_TOKEN`) are end-user runtime config of the shipped binary, read in `apps/cli/src/beeper/`; `apps/www` is a static export with no env. The release job's `HOMEBREW_TAP_TOKEN` lives only on GitHub, as the +public layer prescribes. | Any app, script, deploy or operator step needs an env value or credential: add Infisical. |
| `apps/www` dev server on Next's default port `:3000`                        | It is the repo's only local service, a static site with no backend or database to coexist with.                                                                                                                                                                                                                                                          | It collides with another local stack, or the repo gains a second local service.           |
